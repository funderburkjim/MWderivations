### Поправка к первой формулировке

Первый проход этого разбора относил `ja`/`kara`/`kāra`/`gata`/`stha` к «не словам». **Это было
неверно.** Это kṛt-основы, и как вторые члены *upapada*-татпуруши они полноправные члены
композита: `rāja-kāra` — композит, чей второй член есть основа `kāra`. Они выделены отдельным
классом, но **не** исключены. Настоящее смешение уже́ — только таддхита.

### Отвергнутая эвристика (не воскрешать)

Проверялась гипотеза «настоящее слово встречается и слева, связанный суффикс — нет».
**Опровергнута измерением:** `tva`, `vat`, `mat`, `maya`, `tara`, `tama` встречаются слева (каждый
омографичен самостоятельной основе — `tva-` местоименная, `maya` «состоящий из», `tara`
«переправа»), тогда как настоящее слово `karman` слева **не** встречается. Записано в докстринге
[`classify_uttarapada.py`](https://github.com/gasyoun/MWderivations/blob/master/issue15/classify_uttarapada.py),
чтобы следующая сессия не выводила тот же тупик заново.

### Источник инвентаря — переиспользован, не изобретён

Канонический ярус (14 суффиксов) взят из
[`SanskritGrammar/scripts/sg_wf_004_taddhita.py`](https://github.com/gasyoun/SanskritGrammar/blob/main/scripts/sg_wf_004_taddhita.py)
`SUFFIXES` — того самого списка, на котором стоит опубликованная статья SG-WF-004. Расширенный
ярус (остальные суффиксы Уитни/Макдонелла) держится **отдельным** классом, чтобы всегда было
видно, где выверенное решение, а где экстраполяция. При расхождении ведущим считается список
SanskritGrammar, не этот.

## Use cases

### 1. «Сколько слов оканчивается на `-pāla`?» — 183 или 285, смотря что спрашивать

В issue сказано «`pāla` is a suffix for 285 words in MW». Обратный индекс даёт **183** левых члена.
Это не ошибка ни у одной из сторон, а **три разных множества**:

| множество | величина | что в него входит |
|---|---:|---|
| advanced search «заголовки на `-pāla`» | ~285 | всё, что графически кончается на `pāla`, включая не-композиты и случайные совпадения |
| `compounds.txt`, все токены | ≤285 | только то, что MW сам разметил как деривацию |
| `compounds_reverse_uttarapada.tsv` | **183** | из них только **простые** (`+pāla`), без форм с `-`/`@` |

Практическое правило: **любое число «X слов на -Y» бессмысленно без указания множества.** Для
«сколько композитов с `pāla` вторым членом» верное число — 183; для «сколько заголовков графически
кончается на `pāla`» — ~285. Та же оговорка нужна для любого суффикса при сверке с advanced search.

### 2. Материал для упражнений

`n_left_members` — готовая мера продуктивности: 183 композита на `-pāla`, 358 на `-pati`,
274 на `-karman`. Для дриллов берутся строки класса `UTTARAPADA`; строки `TADDHITA_SUFFIX`
брать нельзя — это не композиты.

### 3. Словарная продуктивность против корпусной засвидетельствованности

Этот индекс — словарная сторона. Корпусная (168 880 разбиений) лежит в
`VisualDCS/derived-data/Kompozity/`, но ключом там служит словоформа, а не член. Джойн даёт то,
чего нет ни у одной стороны по отдельности: «продуктивен по словарю vs засвидетельствован в
корпусе». Спланирован в
[H1328](https://github.com/gasyoun/Uprava/blob/main/handoffs/archive/H1328-Opus_VisualDCS_kompozity-mw-uttarapada-join-dict-vs-corpus_19.07.26.md).

### 4. Чего этот файл НЕ даёт

- **Не покрывает посессивные `-in`/`-mant` и относительные `-ika`/`-ya`** (`-ya` = 1 строка,
  остальные 0) — MW оформляет их иначе. Ровно те суффиксы, которые в SG-WF-004 оказались
  неразмеченными, здесь тоже отсутствуют; как источник по таддхите файл закрывает продуктивную
  абстрактно-материальную группу и не закрывает проблемную.
- **Не различает типы самас** (татпуруша / бахуврихи / двандва) — только members.
- **Не несёт частот** — `n_left_members` это число типов, не токенов.
